## 每张图抄两列

| 截图列 | 抄到 JSON | 注意 |
|---|---|---|
| 机构简称 / 会员简称 | key | 只认表里出现过的简称，见下 |
| 净多单量 / 净空单量（累计） | `cum` | **一律填正数**，方向靠 `side` 表达 |
| 增减 / 今日增减 | `chg` | **原样带符号抄**，正负号不要自己改 |

同一家可能同时出现在净多榜和净空榜（比如某些日子中粮两边都有量）。**按用户的口径只取一个方向**：谁的量在用户关心的那一侧就用哪一侧；两张榜都出现且方向冲突时，先问用户以哪张为准，不要自己抵冲。

## 数字处理

- 单位是**手**，一般不带单位后缀；出现千分位逗号（`119,708`）直接去掉。
- 出现「1.2万」这类写法要先换算成 12000，并在给用户确认时单独说明。
- 累计与增减都是**单边**口径，不要乘 2。
- 截图截断了某列（负数显示成 `-` 或 `…`）时不许猜，列出来问。

## 抄完先做 3 个自查

1. **方向自检**：净多榜抄出来的 6 家，`cum` 都应该是正数；净空榜的 3 家都是负数（写进 JSON 时仍是正数 + `side=short`）。
2. **数量级自检**：和「机构持仓表」第 2 行（上一日）比，同一家的累计不该一天翻倍或腰斩；某家突变超过 50% 时回图核对。
3. **增减自检**：`当日累计 − 当日增减 = 前一日累计`，这个前一日累计应该和表里第 2 行的数基本一致（同一天数据源偶尔有小差异，差 1–2% 属正常，差一个数量级就是抄错列）。

   这条最管用，2026-10-28 那次 9 个数字里 8 个精确对上表内 10-27 行（如高盛 `114312 + 5396 = 119708`、菜粕摩根 `8461 − 6914 = 1547`），剩下 1 个（东证）反算出 14184、表里记 0，说明是**历史行漏录**，不是本次抄错。对不上时先分辨是「抄错」还是「旧数据本来就有洞」，后者报给用户，不要改历史行。

## 常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 抓错合约 | 抄成 05 / 09 的数据 | 认标题里的合约代码，只抄 01（2701） |
| 抓错方向 | 把净空榜当净多榜 | 每张图先看标题那行有没有「净空」 |
| 净空符号反了 | 合计当日增减和案例差一大截 | 净空表的 `chg` 原样抄，脚本会翻转，别手工取反 |
| 前 20 名截断 | 中粮没上榜 | 不许填 0，先问用户 |
| 两个席位 | 「某某期货」出现两次（不同营业部） | 问用户合并还是取大的，不自行相加 |
| 数据日期不是今天 | 截图是昨天的 | 按截图日期写，`--date` 指定 |

## 10% 标注的直观理解

`|看多增量| / |前一日累计| > 10%`，即「一天之内仓位变动超过原仓位的一成」。示例：高盛累计 66570、当日 +17124 → 前一日 49446 → 34.6%，要标；中粮累计 463034、当日 +6637 → 1.5%，不标。
